## 📌 Overview

This project focuses on forecasting electricity demand using **Machine Learning and time-series features**.

The model uses historical electricity demand along with **time-based and weather-related features** such as hour, day of the week, month, temperature, and humidity. Additional lag and rolling statistical features are engineered from historical demand to capture daily and weekly demand patterns.

An **XGBoost Regressor** is trained on historical data from **2020–2023** and evaluated on unseen data from **2024**.

The complete workflow includes:

* Data loading and exploration
* Date/time preprocessing
* Missing-value treatment
* Time-based feature engineering
* Lag feature creation
* Rolling statistical feature creation
* Exploratory Data Analysis
* Time-based train-test splitting
* XGBoost model training
* Model evaluation
* Actual vs. predicted demand visualization
* Model serialization using Joblib

```text

```

### 3. Missing Values

The dataset contains missing values in several columns. The notebook handles them using different approaches:

* **Forward fill (`ffill`)** for temporal features
* **Backward fill (`bfill`)** for temperature and humidity
* **Time-based interpolation** for electricity demand
* Rows containing entirely missing values are removed

## After preprocessing, the notebook verifies that all feature columns contain **zero missing values**.

## 🧩 Feature Engineering

Time-series forecasting benefits significantly from features representing historical demand patterns.

### Time-Based Features

The project creates additional temporal features:

* `weekofyear`
* `is_weekend`

The notebook also explores a holiday feature using the Python `holidays` package, although the `Holidays` column is subsequently removed from the final dataset.

### Lag Features

Two important lag features are created:

```text
Demand_lag_24hr
demand_lag_168hr
```

Where:

* `Demand_lag_24hr` → electricity demand from the same hour of the previous day
* `demand_lag_168hr` → electricity demand from the same hour of the previous week

The weekly lag represents **24 × 7 = 168 hours**.

### Rolling Features

The project also calculates rolling statistics over the previous 24 hours:

```text
demand_rolling_mean_24hr
demand_rolling_std_24hr
```

These features help represent the recent average demand and demand variability.

After feature engineering, rows containing missing values generated by lag and rolling operations are removed.

## 🧪 Train-Test Split

Because this is a **time-series forecasting problem**, the project uses a chronological split rather than randomly shuffling the data.

### Training Data

```text
January 2020 – December 2023
```

### Testing Data

```text
January 2024 – December 2024
```

The split is implemented using timestamp-based Pandas indexing.

This approach ensures that the model is trained on historical observations and evaluated on a later period.

## 🤖 XGBoost Model

The project uses **XGBRegressor** for electricity demand forecasting.

### Model Configuration

```python
XGBRegressor(
    n_estimators=1000,
    early_stopping_rounds=50,
    learning_rate=0.01,
    random_state=42,
    objective='reg:squarederror'
)
```

The model can train for up to **1000 boosting rounds**, with early stopping after 50 rounds without improvement. A learning rate of **0.01** is used.

XGBoost is suitable for this regression task because it can model nonlinear relationships between demand, temporal variables, weather conditions, and historical demand.

---

## 📏 Model Evaluation

The model is evaluated using two regression metrics:

### RMSE — Root Mean Squared Error

RMSE measures the typical magnitude of prediction errors while giving greater weight to larger errors.

### MAE — Mean Absolute Error

MAE measures the average absolute difference between actual and predicted electricity demand.

### Results

| Metric   |    XGBoost |
| -------- | ---------: |
| **RMSE** | **175.21** |
| **MAE**  | **123.48** |

These values are obtained from the notebook's evaluation on the 2024 test set.
